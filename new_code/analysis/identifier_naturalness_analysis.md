## Interpretation

These substitute-preferred rows show that variable-renaming scores are affected by identifier naturalness, but many row-level explanations are uncertain. Some cases are clear, such as `nodesvisited → visited_nodes`, `prevnode → prev`, and `files → file_paths`. In those rows, the substitute is visibly more idiomatic or more precise.

However, many other rows are ambiguous. For example, `column → col`, `combined → merged`, `queue → frontier`, and `steps → moves` involve pairs where both names are common. Other cases, such as `group_by_node → component_by_node`, involve two uncommon domain-specific names. In these rows, the model preference is hard to interpret and may reflect token frequency, local code priors, tokenization, or accidental context effects rather than a meaningful naming improvement.

Overall, this supports the main conclusion: variable renaming is a noisy perturbation axis for exposure detection. The model often responds to identifier convention and local predictability, but many individual preferences cannot be confidently explained. Therefore, original-name preference cannot be cleanly interpreted as memorization unless naming quality, tokenization, and substitute naturalness are much more tightly controlled.
